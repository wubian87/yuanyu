# 种子 · 手机探班

这是一颗"种子"，不是规格书，不是需求文档。
它只钉三件事——y（不变的问题）、验收（怎么算解对了）、押注（往哪个方向解）。
接到这颗种子的 AI：你的活是照 y 和验收长出真能用的东西。
长相、结构、步骤由你定，别把种子当规格照抄。

> v1.3 · 2026-07 · 真用三轮（Ubuntu 本机两版 + 飞牛 FPK 应用化），疤已回填，见文末「成长记录」。本体中 ✅ = 踩过坑确认成立的判断，⚠️ = 坑和解法。

## y

AI 会话在 Ubuntu 上长跑。手机随时打开看一眼回复、塞一句话、关掉。不需要保持连接。

## 验收（按主次）

- 手机打开一个页面，能看到最近一次会话的完整回复内容（不是流式片段，是已经跑完/跑到当前位置的全部输出）
- 手机输入文字发送后，Ubuntu 上正在跑的 Codex/Claude Code 能收到并继续执行
- 手机关掉页面，Ubuntu 上的会话不受任何影响，继续跑
- 再次打开页面，能接着看到新产生的回复
- 局域网内使用，不走外网中转

## 押注

- 一层极薄的 Web 壳：Ubuntu 上一个 HTTP 服务，手机浏览器直连
- 不自己实现 AI 对接——只管把 stdin/stdout 桥接到 Web，AI CLI 是什么就当它是什么
- 手机端不维持长连接，每次打开都是拉取当前终端缓冲区
- ✅ 底座用 tmux 持有 AI 进程（验证成立）：codex 等会拒绝非 TTY 的 stdout，tmux 给的伪终端正好满足；关浏览器/断网进程不死
- ✅ 不走 ttyd 那条 WebSocket 长连接的路：ttyd 最小化即断、会话随之丢；tmux 的会话保持才是「关了不受影响」的解法

## 空气

- 目标环境：本机 Ubuntu + 局域网内任意手机浏览器
- 主要伺候 Codex 和 Claude Code 两种 CLI
- happy 已经在用，但太重了（云中转、加密、daemon、独立 App），参考它的 stdin/stdout 桥接思路，但砍掉所有不需要的
- 手机浏览器后台标签页容易被系统杀——不要依赖 WebSocket 长连接或 SSE 流式推送
- 这人会用 Codex 的 `app-server` 模式和 Claude Code 的普通 CLI 模式，两种 stdin/stdout 协议不同，但对你来说都一样——就是读写一个子进程
- 另有一台飞牛 NAS 上跑着 ttyd 方案（Web 终端包装 ttyd/xterm.js），除了「最小化就断会话」都挺好——这是 tmux 路线的直接对照组

## 成长记录（只增不改）

**版本史**：v1.0 出厂（2026-07，Ubuntu 本机）→ v1.1 第一版基础桥接（看/发/信号）→ v1.2 第二版会话管理与 TUI 按键 → v1.3 第三轮飞牛 FPK 应用化。三轮均未动 y。（存疑待真人封口：y 写死了"Ubuntu"，第三轮已长到飞牛 fnOS——要不要放宽成"一台长跑的 Linux 机器"，动 y 就跳 v2。）

**产出落点**：Ubuntu 本机 `phone-probe/`；飞牛版 `fpk/phone-probe/`。

### 架构判断（第一版）✅
- tmux 是对的底座。`tmux new -s ai -d 'codex'` 起会话，探班用 `capture-pane` 读画面、`send-keys` 写按键、`respawn-pane` 重启进程。全 stdlib Python HTTP，零依赖。
- ttyd 的会话保持是短板：它每连一次 fork 一个新 PTY+shell，断了就死。tmux 天然分离「会话」和「连接」，才是「关了不受影响」的解。飞牛那边若要修「最小化退出」，正解是让 ttyd 跑 `tmux new -A -s main` 而不是裸 shell。

### 会话管理（第二版）✅
- **并行多会话**是刚需，不是锦上添花。`tmux new-session -d -s <名> <cmd> -c <目录>`，探班用 `?session=xxx` 在 API 层切换盯哪个。一个浏览器同时管着 ai / ai2 / coding 多个会话，互不串台。
- **CLI 类型可切**：建会话时选 codex 还是 claude，本质就是改那条启动命令。**白名单写死**（只允许这两个字符串），绝不能让前端传任意命令——防注入。
- **工作目录可设**：tmux `-c <目录>`。后端必须校验目录真实存在（`Path.is_dir()`），防目录穿越。
- **会话名校验**：只允许 `[A-Za-z0-9_-]+`，禁止空格特殊字符（tmux 命令解析会出错）。前后端都校验。探班自己的会话名（如 `probe`）要占位保护，不准建同名、不准杀。
- **结束会话 = `tmux kill-session`**，彻底杀掉。不需要「历史会话」概念——tmux 会话没了就是没了，探班不额外记账，省心。

### 边界澄清（重要）
- **探班不碰 API key / 模型**：用 gpt 还是 claude 还是 deepseek，是 codex/claude 自己的配置（`~/.codex/config.toml`、`~/.claude/settings.json`）。探班只决定「窗格里跑哪个 CLI、在哪个目录」，决定不了「CLI 打电话给哪个模型大脑」。想换模型先去配 CLI 的 key，探班无能为力。

### 踩过的坑 ⚠️
- **ANSI 颜色会断**：清洗终端输出时不能删 ESC(0x1b) 字节。ESC 是颜色序列的开头，删了 `[32m` 就变成裸 `[32m`，全屏没颜色。C0 控制字符过滤要把 ESC 留出来。
- **前端 class 名要对齐 ansi_up 输出**：ansi_up 用 `use_classes` 时输出 `ansi-green-fg`，CSS 得写 `*-fg`/`*-bg`，不是 `ansi-green`。
- **斜杠命令通过 Web 桥可以可靠执行**（更新：原以为不可靠，找到解法了）：codex/claude 的 `/clear`、`/new` 是 TUI 命令，靠「菜单选中」触发。解法是给前端加 **方向键 ↑↓ + 回车 + ESC** 四个按键按钮——打 `/` 弹菜单，↑↓ 选中，回车执行，ESC 取消。这样斜杠命令能稳定触发，不必每次都靠重启进程清上下文。（重启进程 `respawn-pane -k` 仍是兜底手段，重启后记得 `clear-history` 清滚动历史。）
- **后台进程会随 shell 被回收**：在非交互 shell 里用 `nohup … &` 不一定稳，进程可能随命令结束被 SIGKILL。把探班自己也丢进 tmux 跑（`tmux new -s probe …`）最稳，跟 AI 会话同构。

### 启发式而非协议
- 「AI 状态」（思考中/输出中/待命）没有协议层信号，靠扫终端尾部画面 + 画面变化率推断：codex 干活时尾部有 `Working`/`esc to interrupt`，claude 类似有 `Esc to interrupt`；画面在变长=输出中，稳定不动≈待命。够用，别指望 100% 准。

### TUI 按键操作（第二版）✅
- AI CLI 是 TUI，光靠「发文本」不够，得能发**按键**。后端 `send-keys` 支持的 key 名：`Up/Down/Left/Right`（方向键）、`Escape`、`C-c/C-d`、`Enter`。前端给 ↑↓↵ESC 四个按钮，就能操作 codex/claude 的菜单（选斜杠命令、翻历史选项、退出弹窗）。
- 手机上 TUI 的精细键盘交互（方向键选菜单）原来是个盲点，加按键按钮后通了。别只做「文字输入」，按键是 TUI 桥接的另一半。

### UI 经验（第二版）
- 零散功能收进**右上角抽屉菜单**（会话列表/新建/结束），别铺在主界面——手机屏小，主界面要让位给终端内容。
- 按钮颜色要**安静**：终端内容是主角，控制按钮压成低饱和暗色，只在按下时微微显色反馈。亮蓝/红/黄按钮会分散注意力。
- 输入框聚焦给个**柔和发光**（box-shadow 外圈），有「正在输入」的精致感。
- 「暂停/继续轮询」按钮实测没用，删了。轮询本来就很轻，省那点电不如换界面干净。

### 飞牛应用化（第三轮）✅
- 已做成飞牛 FPK：源码在 `fpk/phone-probe/`，当前验证版本 `0.1.4`，安装包 `phone-probe-0.1.4-arm.fpk`。应用名 `phone-probe`，显示名「手机探班」，监听端口 `17682`。
- FPK 很小：不打包模型、不打包 Node/Go、不打包 ttyd。主要是 Python stdlib 后端、HTML/CSS/JS、图标，包体约百 KB 级。依赖 NAS 上已有 `python3`、`tmux`、`claude`/`codex`。
- 飞牛应用 `start` 时把探班服务放进 `tmux` 会话 `probe`：`tmux new-session -d -s probe ... server.py -s ai --port 17682 --no-check`。这比 `nohup &` 稳，和 AI 会话同构。`probe` 是基础设施会话，前端会话列表要过滤掉，也不能让用户杀。
- 探班服务必须以普通用户空间跑（实测用 `xin`），不要让 AI CLI 跑成 root。服务 `PATH` 要包含 `/vol1/1000/fn-file/bin`，否则 NAS 上可能找不到 `claude`。
- 飞牛 NAS 上实测有 `python3`、`tmux`、`claude`，未必有 `codex`。飞牛版默认 CLI 选 `claude --permission-mode bypassPermissions`，但保留 `codex` 选项，等以后装了 codex 可用。
- **默认工作目录**：新建会话如果前端 `cwd` 留空，后端必须显式用 `/vol1/1000`。否则 tmux 会继承探班服务当前目录，落到 `/vol1/@appcenter/phone-probe/server` 这种应用安装目录里，不适合 Claude/Codex 工作。显式传目录仍要 `Path.is_dir()` 校验。
- 直连入口是 `http://<NAS>:17682/`；飞牛桌面入口只是一个 iframe 外壳，走 `/cgi/ThirdParty/phone-probe/index.cgi/` 读取状态并嵌入直连页面。

### 飞牛 UI 取舍（第三轮）✅
- 飞牛桌面窗口本身已经有系统标题栏和边框，不要再在应用内部画一层「手机壳」。实测会出现双重外框、黑边很重、比例不协调。
- 最终取舍：飞牛入口**直接全窗口嵌入探班页面**，不做手机框、不固定 9:16/9:19.5 比例。电脑宽窗口自然宽屏，手机直连自然竖屏。不要额外放「新窗口」「刷新」按钮，用户明确觉得多余。
- 早期尝试的竖屏手机壳会让终端区域变窄，Claude/Codex 输出容易横向溢出，浏览器滚动条破坏观感。若以后做窄屏优化，应优化探班页面自身的响应式，而不是外层套壳。
- 内层探班页为了手机/飞牛更舒服：终端内容可 `pre-wrap`/`overflow-wrap:anywhere`，隐藏显眼滚动条，底部输入区不要太高。否则在飞牛窗口里会出现白色横/竖滚动条。

### 飞牛打包/安装坑（第三轮）⚠️
- 本地 Ubuntu 没有 `fnpack` 时，`build.sh` 会停在 `fnpack not found`，但已经刷新 `package-src/`；要把 `package-src` 传到 fnOS NAS 上用 `/usr/local/bin/fnpack build -d package-src` 打包。
- 飞牛 `install-fpk` 对同 appname 同/近版本可能不会覆盖 `/vol1/@appcenter/<app>/www` 等已安装文件，实测会导致旧前端残留。稳妥做法：升版本号 + 卸载重装，或者至少验证安装目录内容。
- 飞牛 WebView/桌面可能缓存前端资源。每次改前端要同步升 manifest 版本、`ui/config` 入口 `?v=`、`www/index.html` 里的 CSS/JS `?v=`。`build.sh` 可用 `sed` 自动对齐缓存戳。
- `appcenter-cli start phone-probe` 偶尔返回 `code 10500`，但实际服务可能已经启动。不要只看返回码；要同时查 `appcenter-cli status phone-probe`、`tmux ls`、`ss -ltnp | grep 17682`、`curl http://127.0.0.1:17682/api/health`。
- Python 运行会生成 `__pycache__`，打包前清理；服务启动时设 `PYTHONDONTWRITEBYTECODE=1`，避免安装目录里运行后又生成缓存。
- `curl -I` 探测探班 HTTP 会得到 501，因为后端没实现 HEAD；飞牛状态 CGI 应用 GET `/api/health` 探测。
- 图标可以用 ImageMagick 生成 `icon_64.png` / `icon_128.png` / `icon_256.png`，同时复制 `ICON.PNG`、`ICON_256.PNG` 进 FPK 根目录。飞牛桌面图标不是功能核心，但用户会在意"像正式应用"。
