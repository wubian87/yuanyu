# 种子园 · 园规

> 这份文件在真实的种子园里叫 `CLAUDE.md`，放在园根，AI 进园干活先读它。这里作为示例收录：种子出厂之后，就是这么活的。

种子园是原语言种子出厂后的**成长家**。这里不是实验场：没有预注册、没有盲测、没有报告、没有台账。种子长，园主调整。

## 布局

```
种子园/
├── CLAUDE.md      ← 本文件（园规）
├── 原语言/        ← 工具棚：原语言本体 + 使用说明（发行版拷贝，源头升版本这边手动换新）
├── 知常/          ← 地块：种子 + 门规 + z，自带 git
├── 随身门/        ← 地块
└── 烛息/          ← 地块
```

一颗种子一块地。地块自带 git（种子跟 z 一条历史），园根的 git 只管园规和工具棚，不伸进地块。

## 两种活，别混

- **进地块干活（长 z / 改 z）**：工作目录设到那块地，读它的 CLAUDE.md 门规——种子是唯一需求源，长相你定，种子正文不动。
- **改造种子本身（园主带着做）**：把 `原语言/原语言.md` 单文件丢给 AI 说"开始"，对象就是那颗种子和它地里暴露的疤。改造的输入必须来自真用（z 跑过、身体判过），不是坐着想出来的——先跑，后想。

## 户口制度（改种子的规矩，每块地通用）

- 一个 y 一个文件，文件名内文同名。
- **回疤跳小版本**（v1.0 → v1.1）：y 不动，把真用暴露的坑写回验收/押注/空气。
- **动 y 跳大版本**（v1 → v2）：问题本身变了——按户口这其实是另立新种子，想清楚再动。
- **成长记录只增不改**，写在种子文末。
- 每次改种子，在那块地 git commit，message 中文写"为什么"。
- 拍板的人永远是园主：AI 可以提刀，落刀只有他。

## 新种子入园

在园根开新目录：`种子.seed.md` + 门规 CLAUDE.md（抄现有地块的骨架改特殊处）+ `git init`。种子从哪来，原址留一行指针。
